# くらしのレシート v1.0 — 無料の商品名・特徴からの分類予測

Android / Windows 共通PWA。v0.9までの学習・予測、v0.8の食費内訳、v0.6の計上月配分、Supabase同期とOCRはそのまま引き継ぎます。

## 追加機能

- OCRで初めて認識した商品名を、既存の修正履歴だけでなく、商品名の言葉・表記揺れ・容量などで推測します。
- 例：「ムセンアカフジ5kg」→「食材 → 米・麺類」。理由は「ムセン（無洗米の略称候補）」「アカフジ」「5kg（補助情報）」と表示します。
- 「5kg」という重量だけではお米と断定しません。複数カテゴリーが接戦なら自動確定しません。
- 「学習・予測」→「未登録の商品を分類予測」で商品名を入力すると、**根拠と判断レベルを確認**できます。試すだけでは学習・購入履歴を変更しません。
- 修正ルールの完全一致を最優先します。非常に似た学習済み商品も分類の参考にしますが、容量違いなどでは元の名前を勝手に書き換えません。
- 自動登録した明細に分類の判断があいまいなものがあれば「要確認」の購入として保存します。
- 手動登録欄の商品名の編集でも分類候補を表示し、利用者が手動で分類を選んだ後は自動で上書きしません。
- 商品名から `5kg` や `300g` などが見つかれば、OCR登録時の容量・単位へ利用します（自動分類に成功した場合）。

## 更新手順

1. **更新前に**現行版の「設定」→「JSONバックアップを書き出す」でバックアップを取ります。
2. このZIPを解凍し、ファイルをすべてGitHubの `highllows-stack/receipt-ledger` `main` ブランチのルートにアップロードします。`smart-classify.js` が新しく追加されます。
3. Github Pagesの公開が完了したら `https://highllows-stack.github.io/receipt-ledger/?v=1.0` で開きます。キャッシュが残る場合は `Ctrl + Shift + R` を押してください。
4. 「学習・予測」→「未登録の商品を分類予測」で `ムセンアカフジ5kg` を入力して試します。
5. 実際のレシートをテストする場合は、分類が正しいか「履歴」で確認してください。

## 無料運用と注意

- **追加の有料AI/API呼び出しはありません。** JavaScript内の辞書・類似文字列判定と既存のSupabase学習ルールを利用しています。
- Google Cloud Vision OCR自体は従来どおりGoogle Cloud経由で呼び出され、同社の無料枠や課金条件が適用されます。Supabaseも無料利用枠内が前提です。
- v0.9の `learning-migration.sql` を適用済みであれば **追加SQL・Edge Function更新は不要**です。まだ学習機能のSQLを適用していない場合はv0.9の手順が必要です。
- 過去の購入履歴や確定した手動分類を一括変更する処理はありません。予測は今後のOCR登録・手動入力欄で適用します。
- 商品名からの推測であり、意味を理解する有料AIモデルではありません。未知のブランドや誤OCRに対応できないことがあります。誤認識時は手動編集し、学習ルールを蓄積してください。
- GitHubアプリ連携には直接書き込み権限がないため、こちらで公開リポジトリは更新していません。従来と同様にZIPのアップロードが必要です。
