# くらしのレシート v1.5 — 税抜のまま保存された購入履歴の税込補正

Android / Windows 対応PWA。v1.4のOCR・非公開写真・90度回転・学習・予測・価格比較・月別配分・食費グラフ・クラウド同期を継承します。

## 今回の不具合と対策

2026-10-23 の maruetsu の履歴は、v1.4で誤認識12商品・¥14,422から9商品・¥1,600（税抜）に修正した場合、従来の「写真照合済み修正」ボタンが表示されなくなる不具合がありました。そのため消費税¥128を登録明細へ加算できませんでした。

v1.5では **両方の誤登録状態**に対応します。

- 旧状態：12商品／¥14,422 → 9商品・11点／税込¥1,728への写真照合済み修正
- 中間状態：9商品／税抜¥1,600 → **商品名・既存のID・数量・月別配分・保存写真を維持**し、印字税額¥128を各明細へ配分して税込¥1,728に修正
- 未分類になっていた商品は、今回写真で確認できた品名についてのみ大分類／小分類を補完（利用者が変更した分類を上書きしない）
- 同じ商品名（例：ドリンクゼリー）を2行購入していても、行を合体させずそのまま保持
- 商品ごとの税額は印字された税額を数量比ではなく**商品行の税抜金額比**で按分。円単位で端数調整し、明細合計が¥1,728になるようにする（税抜¥108の行は税込¥116または¥117となる場合がある）
- すでに税込へ換算した明細へ税を二重加算しない
- **他のレシートでも使える税込補正欄**を編集画面に追加。写真に記載された消費税額と税込合計を入力して按分できます。全明細が税抜表示のときだけ利用してください。8%と10%混在など税率区分が異なる場合は、分類・小計の確認が必要です。
- いずれも**編集欄だけを変更**し、最後の「変更を保存」を押すまで購入履歴には反映されない

## 更新方法

1. 旧版で「設定 → JSONバックアップを書き出す」を押して保管します。
2. このZIPを右クリックで「すべて展開」します。
3. ZIP内のWebアプリ用ファイル15個を `https://github.com/highllows-stack/receipt-ledger/upload/main` にアップロードし、GitHubで `Commit changes` を押します。
4. `https://highllows-stack.github.io/receipt-ledger/?v=1.5` でバージョン表記「税込金額修正・写真回転 v1.5」を確認します（必要ならCtrl+Shift+R）。
5. 「履歴 → maruetsu 2026-10-23 → 購入全体を編集・明細を分割」で、上部にある「今回のまるえつレシートを正しい明細に修正」を押し、確認ダイアログを承認します。
6. 商品9行・数量11点・税込合計¥1,728・各商品分類・計上月を確認し、**「変更を保存」**を押します。

一般の税抜レシートでは、編集画面の「税抜の明細を税込に補正」へ「レシートに印字された消費税額」と「税込合計」を手入力してボタンを押します。商品金額+税額と税込合計が一致しない場合は補正を拒否します。商品ごとの表示税率の違いがある場合は、この一括按分機能を使用せず個別に編集してください。

## 追加設定・費用

今回の更新ではSupabase SQLやEdge Functionの更新は不要です。OCR再呼び出しもしません。前のバージョンのレシート写真は引き続き非公開領域に保存されます。

## 動作確認

PC幅1280px／スマホ幅390px相当のブラウザで、税抜¥1,600の9行を税込¥1,728へ変換し、税額の円単位配分、数量11点、商品ID、月別配分、保存前に履歴を変更しないこと、保存後の¥1,728反映、二重課税防止、および他の税抜例¥800＋税¥80＝¥880をテストしました。

**実際のSupabaseへの書き込み、Google Visionの新規OCRは実機環境では未テスト**です。写真と照合し、保存後に一覧へ¥1,728と表示されるかを確認してください。
