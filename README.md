# くらしのレシート v1.9 — 合計金額の誤読防止・商品ごとの電卓

Android / Windows対応の既存家計簿PWAの累積更新版です。v1.7の割引・数量・税額照合、v1.8のg/kg/個/本/分数配分、v1.6以前の商品学習、非公開レシート写真、OCR、自動分類を引き継ぎます。

## v1.9の改善

1. **「お預り1,777円」を「購入合計1,777円」と誤認しない**よう、商品小計・印字税額・合計・預り金・釣銭を別々に判定。検出した「合計候補」が預り金または税額から導いた合計と矛盾すれば破棄して「要確認」にします。
2. **商品を読み落としたまま数字を揃えない**。例：2026/10/24のマルエツでキャベツ109円・ウインナー199円しか読めなかった場合、商品合計308円、印字小計576円、税額46円、合計参考622円と別々に表示し「商品1点不足」と警告します。豚肉を自動で捏造しません。
3. **全商品に個別の電卓を配置**。編集画面で商品ごとの税込金額欄の直下に「🧮この商品の電卓」。計算式 `384-116`、`(384-116)*1.08`、`108*1.08` や税率ボタンで計算した後「この商品に入力する」でその商品だけ更新。電卓は写真を見ながら商品カードの中で使えます。
4. **既存の間違ったレシートを再編集**。編集画面の「OCR原文から明細を再作成」では、元の商品・計上月の保護を試み、確認後の「変更を保存」まで元の履歴を変更しません。すでに添付済みの2026/10/24写真は「10月24日レシートを修正」ボタンも使えます（データと日時の整合条件を満たす場合のみ表示）。
5. **不明なレシート合計を勝手に明細合計で置き換えない**。Supabaseでは receipt_total に NULL（不明）を保持可能です。登録済み履歴は更新するまで自動修復されません。
6. **ファイルURLに v1.9.0 を付けたため、旧版JSとの混在を避けやすく**しました。Service Workerのキャッシュ識別子も変更しました。

## マルエツ 2026/10/24 の写真で確認した正しい数字

- 豚肉ロース生姜焼 税抜384円 → 自動割引 -116円 → 税抜268円
- キャベツ 税抜109円
- ウインナー5本 税抜199円
- 小計3点・税抜576円、8％外税46円、合計税込 **622円**
- 預り1,777円・釣銭1,155円は購入商品金額ではありません。
- 商品ごとの税込配分額は豚肉289円、キャベツ118円、ウインナー215円（合計622円）です。印字税額をまとめて按分し、円単位の端数を調整しています。

## 更新方法（SQL・Edge Function更新不要）

1. **現在のアプリから「設定 → JSONバックアップを書き出す」**（別ファイルとして保管）。
2. ZIPを解凍し、展開したWebファイル15個を `https://github.com/highllows-stack/receipt-ledger/upload/main` へアップロードして Commit changes。ZIP自体をアップロードしない。
3. GitHub Pagesへの公開が反映された後 `https://highllows-stack.github.io/receipt-ledger/?v=1.9` を開き、上部の **「合計照合強化・商品別電卓・配分 v1.9」** を確認。
4. 「履歴 → 該当購入 → 購入全体を編集」を開き、古い誤認識が残っている場合は写真照合済み修正ボタンまたはOCR原文の再解析を使用する。保存する前に税込合計が622円か確認。
5. Chrome/Firefoxのブラウザデータ全削除はしない（端末ローカル履歴が消える可能性あり）。画面が古い場合はCtrl+Shift+R、PWAを完全に終了して再起動して確認。

### 注意

- 商品名や税額自体をGoogle Visionが読み落とした場合、文字列の再解析だけでは復元できません。写真を見て編集するか、追加のOCR実行が必要です。追加OCRには既存Google Visionの料金・無料枠条件が適用されます。
- 計上月・配分、学習ルールと写真は現行データ構造を利用します。**新しいSQLは不要**。
- テスト：JavaScriptの構文検査、分割OCR・預り金の誤認識・商品欠落の解析、PC/モバイル相当ブラウザで商品別電卓の計算・反映を確認。実際のSupabase・OCR再実行は更新後の実機確認が必要です。
