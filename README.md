# くらしのレシート v0.6 ― 計上月・数量按分・集計内訳

Android/Windows PWA。以前の購入履歴・レシートOCR・Supabaseログインを引き継ぎます。

## 何が新しくなったか

- 購入日と「計上月」を区別。新規手入力の**商品ごと**に計上月を選択可能。
- 既存購入／OCR登録済み商品も「履歴 → 購入全体を編集・明細を分割」から計上月を変更可能。
- 一つの商品の金額を複数月に配分。金額を直接入力するか、購入数量・容量と月別配分数量から自動計算。
- 購入金額と月別計上額の合計が違う場合は保存不可。数量を入力した場合は全月の数量が購入数量に一致することを検証。
- 集計：**計上月**と**購入月**を切り替え。大分類→小分類→商品明細に展開、6か月の推移を確認。
- 購入履歴で商品の計上月と金額を表示。CSVにも計上月・月別金額を分けて出力。
- JSONバックアップにも配分データを含めます。

## 必ずこの順序で更新してください

1. **現行アプリの「設定」→「JSONバックアップを書き出す」** を行い、ファイルを残します。
2. SupabaseのSQL Editorで **`allocation-migration.sql`** を全文実行します。`Success. No rows returned` なら正常です。以前の購入データは削除しません。再実行しても問題ない構造です。
3. **このZIPのうちWebアプリ用ファイル**（`index.html`, `app.js`, `cloud.js`, `editor.js`, `ocr-parser.js`, `receipt.js`, `sw.js`, `style.css`, `manifest.webmanifest`, アイコン）を、以前と同じGitHubリポジトリ `highllows-stack/receipt-ledger` のルートにアップロード、同名ファイルを置換します。`allocation-migration.sql` のGitHubアップロードは不要です。
4. GitHub Pagesの処理を待ち、`https://highllows-stack.github.io/receipt-ledger/?v=0.6` をChromeで開きます。古い表示なら `Ctrl+Shift+R` で再読み込みします。
5. 最初は過去の米1件で、購入日を残したまま月別配分を試して、PC・スマホ双方の表示を確認します。

## 例：2,380円・5kgの米を10月・11月に分ける

1. 「履歴」で米の購入を開き、「購入全体を編集・明細を分割」を押します。
2. 商品の「数量」は1、「容量・重量」を**5**、「単位」を**kg** にします。
3. 「何月分として計上するか」の1行目を10月、配分量**2**に設定。
4. 「＋月を追加」で2行目を11月、配分量**3**に設定。
5. 「数量比で金額を自動配分」を押すと、10月分**952円**、11月分**1,428円**となります。
6. 「変更を保存」を押し、「集計」で10月・11月の内訳を確認します。

重量が正確に不明な場合、月別の「計上金額」を直接入力できます。配分量を使わない場合は空欄のままでよく、各月の金額合計だけ一致させます。

## 大切な注意点

- 月別計上は**家計管理上の任意の配分**です。実際の購入日・支払い金額は変えません。税務上の会計処理を自動で判断するものではありません。
- 旧データに計上月情報がない場合、従来の購入月に全額計上します。既存の購入データは自動改変しません。
- 商品金額を編集した場合、複数月の配分金額も合わせて変更してください。1か月だけの配分は金額に合わせて自動更新します。
- 既存のOCR用Edge FunctionとGoogle APIキーの再設定は不要です。
- **クラウド同期の実機テストは利用者のSupabase環境で必要です**。変更前のJSONバックアップを保管してください。
- OCR誤認識があれば従来どおり履歴で修正できます。画像は保存しません。
- SQL移行が完了していない状態でv0.6のクラウド保存を試すと失敗します。先にSQLを実行してください。
