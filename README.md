# くらしのレシート v2.1 — OCR金額の矛盾検査・誤った税込合計の防止

v2.0までの機能（写真の回転・写真付き編集、商品別電卓、月別重量・割合・金額配分、学習・予測、Supabase同期）を引き継ぐ累積更新版です。

## なぜ修正したか

2026年10月24日のマルエツのレシートは、税抜小計576円、8%消費税46円、税込合計622円、預り1777円、釣銭1155円です。OCRが「小計46円・税額622円・合計1198円」と誤認識したとき、旧版は576+622=1198円を誤って参考合計としました。

## 変更内容

- **税額の妥当性を必ず検証**: OCRで得た金額が税抜額の8%/10%と矛盾する場合、印字税額として使いません。複数税率は税額合計と税率別内訳を検証します。
- **独立した3つの金額根拠を照合**: 「税抜小計＋税額」「印字された合計」「預り金−釣銭」が矛盾すると、誤った税込合計を確定しません。
- **OCRの2種類の読取り結果を別々に検証**: 行の位置情報と通常のOCRテキストを不用意につなげて、別のラベルと数値が結び付かないようにします。
- **矛盾した数値は保留**: 例「税額622円」を「税額として不採用」と表示します。税込への自動変換で捏造しません。
- **現金差額等からの参考計算を区別**: 印字税額を確認できなくても税抜小計576円と現金差額622円が整合する場合、税額46円を「参考推計」と明記。印字済みの税額とは区別し、「要確認」を残します。
- **明細と参考合計の差額表示**: 印字された合計自体が読めていなくても、預り−釣銭からの参考合計と明細との差を表示します。
- **税込参考合計を編集欄に入力**: 確認ボタンで参考合計を編集欄に反映できます。**商品明細は自動で書き換えず、最後に「変更を保存」を押すまで履歴には反映されません。**
- **10月24日の既存699円などの誤登録修正**: 以前からある「写真照合済み3商品・税込622円に修正」のボタンを引き続き使用できます。

## インストール

1. 旧版の「設定 → JSONバックアップを書き出す」で必ずバックアップを保管します。
2. ZIPの**中身15ファイル**をGitHubリポジトリ `highllows-stack/receipt-ledger` の `main` ルートへ上書きアップロードし、Commit changesを押します（ZIP自体はアップロードしません）。
3. `https://highllows-stack.github.io/receipt-ledger/?v=2.1` を開き、見出し「税額の誤読防止・金額証拠照合 v2.1」を確認します。古い版が表示される場合はCtrl+Shift+Rまたはアプリの再起動を行い、ブラウザデータ削除はしないでください。
4. 「履歴 → 2026年10月24日のmaruetsu → 購入全体を編集」を開き、「写真照合済み3商品・税込622円に修正」を使って商品・税額・計上月を確認し「変更を保存」。

**今回、追加のSupabase SQL・Edge Function設定変更は不要**です。OCR再処理は保存された文字列・位置情報だけを使う限りGoogle Visionの追加呼び出しは不要です。写真を再OCRする場合は従来のGoogle Cloud Vision利用条件が適用されます。

## テスト範囲・注意点

- JavaScript構文チェックと、実際に送られたレシートの金額を転記した回帰テストに加え、誤読（金額入替・異常税額・税額の読み落とし）、税込表示、8/10%混在、商品欠落のケースでチェックしました。
- この環境ではChromiumからlocalhostへのブラウザ接続が管理者により遮断されたため、画面の実動作テストおよび本番Supabase接続は未確認です。表示または保存で問題があればメッセージとスクリーンショットを確認します。
- OCRが商品名や価格そのものを読み落とした場合、数値の一致だけで商品を復元することはできません。写真を見ながら修正してください。
- **既存履歴は更新だけでは修正されません**。修正ボタン等で候補を確認し、保存してください。
# v2.2 更新内容（2026-10-25）

- 商品別の電卓に「％引き」「円引き」の入力を追加。割引後の計算式を確認して商品金額へ反映できます。割引率は0～100％、円引きは商品金額以下に制限します。
- OCRの金額ラベルが誤認識された場合、税率上あり得る「小計＋税額＝税込合計」の数字の組み合わせを**参考候補**として表示します。印字根拠が不確かな数字は自動的に税込合計・税額へ採用しません。
- PWAキャッシュをv2.2へ更新。

# v2.3 更新内容（2026-10-25）

- Google Visionが小計・税額・合計・預り・釣銭の「見出し列」を先に、その後「金額列」を続けて出力した場合、預り－釣銭＝税込合計および小計＋税額＝税込合計を独立検証したうえで対応付けます。
- 「商品名／割引の見出し／商品価格／マイナス割引」の順に出力されるOCR原文でも、割引を直前の商品に適用します。
- 2026年10月24日のマルエツ目黒店のOCR原文で、豚肉268円・キャベツ109円・ウインナー199円、税抜小計576円・税額46円・税込622円が完全一致するテストを追加しました。
- v2.2で追加した％引き・円引き電卓も引き続き利用できます。

# v2.5 更新内容（2026-10-25）

- 調味料の小分類に「料理の素」を追加（うちのごはん、麻婆豆腐の素、Cook Do、鍋の素など）。
- 食品・飲料の小分類に「デザート・ヨーグルト」を追加（ヨーグルト、プリン、ゼリー、杏仁豆腐など）。
- OCRの自動分類辞書と手入力時の簡易分類に新分類を追加。牛乳・チーズ・卵は引き続き食材の「卵・乳製品」。
- 学習済みの分類・既存購入履歴は自動変更しません。画面表記とキャッシュをv2.5に更新。

# v2.6 更新内容（2026-10-25）

- 購入履歴の編集画面に「詳細編集」「カテゴリーだけ編集」の切り替えを追加。
- カテゴリー専用画面では各商品の名前と税込金額を読み取り専用で表示し、大分類と小分類だけ編集します。
- 分類選択は詳細編集の入力欄へ同期し、「変更を保存」で既存の保存処理を利用。数量・金額・月別配分は変更しません。
- OCR再解析で商品行が入れ替わった際は、カテゴリー専用一覧も再描画します。
- 画面上部と読込ファイル・PWAキャッシュをv2.6へ更新。

# v3.1 更新内容（2026-10-25）

- 大分類「外食」を追加（レストラン、ファストフード、カフェ・喫茶、麺類・ラーメン、テイクアウト、その他）。明確な飲食店・デリバリーサービス名の自動分類候補にも対応します。
- 「食費全体・選択科目の内訳」では、チェックボックスで複数の大分類を選び、その合計金額を1つの円グラフの小分類内訳として表示できます。
- 初期選択は食材・調味料・食品・飲料・外食。食費全体への戻しと、全科目を選択するボタンを追加しました。
- 円グラフから小分類・商品へ移動する既存のドリルダウンは維持します。SQL変更はありません。

# v3.0 更新内容（2026-10-25）

- 円グラフの「食事区分」で朝食用・昼食用・夕食用の扇形または凡例を押すと、購入先・購入日・商品名・分類・その区分への計上金額を明細表示します。
- 対象月の計上月／購入月の選択と連動し、1商品が複数の食事区分に分かれている場合も各区分に対応した金額だけを表示します。
- 「内訳を閉じる」でグラフに戻れます。SQL変更や既存データの変換は不要です。

# v2.9 更新内容（2026-10-25）

- 「円グラフの分類」の選択肢に「食事区分（朝食・昼食・夕食）」をHTMLから直接表示。これまでの動的追加にも対応したまま二重登録を防ぎます。
- 「食品・飲料」に小分類「おやつ・間食」を追加。お菓子や間食の認識候補にも使用します。
- 大分類「その他」に小分類「その他」を追加し、「未分類」と区別して手動で選べるようにしました。
- 既存商品を自動的に別の分類へ書き換えることはありません。データベースのSQL変更は不要です。

# v2.8 更新内容（2026-10-25）

- 支出ダッシュボードの「円グラフの分類」に「食事区分（朝食・昼食・夕食）」を追加。食費（食材・調味料・食品・飲料）だけを対象月の配分額で表示します。
- レシート編集画面の最上部に「詳細編集／カテゴリー・食事区分だけ編集」切替を移動。
- 両方の編集モードで、朝食・昼食・夕食への全額指定をワンタッチ化。「金額・割合で分ける」を押したときのみ配分入力を表示。比率は端数まで商品総額に一致させます。
- 未操作時は従来どおり全額夕食用。データベース追加変更はありません（v2.7のSQLを適用済みの場合）。

# v2.7 更新内容（2026-10-25）

- 商品ごとに朝食用・昼食用・夕食用へ税込金額を配分。合計が商品金額に一致した場合のみ保存できます。
- 未設定・旧データは全額夕食用扱い。商品編集中の詳細画面と「カテゴリー・食事区分だけ編集」の両方から配分可能。
- 月別ダッシュボードに「食事区分別の食費」を追加。計上月モードでは商品の月別計上額に比例して食事配分を集計。
- Supabaseを使う場合、最初に `meal-allocation-v2.7.sql` をSQL Editorで一度実行してください。既存購入を削除・変更しません。
- 端末内のバックアップには新しい `mealAllocations` フィールドが含まれます。旧バックアップも夕食100%として扱えます。
- OCR照合や割引電卓、カテゴリー専用編集の既存機能は維持しています。
