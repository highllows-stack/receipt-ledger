# くらしのレシート v1.4 — 税抜→税込の明細修正と即時写真回転

Android / Windows PWA。「写真確認 v1.1」「税額照合 v1.2」「数量・画像回転 v1.3」に対する修正です。月別配分・食費グラフ・学習ルール・クラウド同期の既存機能は引き継ぎます。

## 今回の修正

### 一般のレシート解析

- 「小 計 / 11点 1,600」のような、小計と点数と金額が別行に印字されるレシートを認識。
- 「(8%外税額 ¥128)」のように括弧付きの税額を認識。旧版は末尾の閉じ括弧のため、消費税を検出できないケースがありました。
- ポイント番号・カード番号・レジ番号・品番・小計以降の精算情報を商品として登録しない判定を強化。
- 税抜小計と明細が一致し、税額が印字されているときは、印字合計が読めなくても税額を明細に配分して参考税込金額を算出（合計印字不明として「要確認」）。
- レシートの印字税込合計が読み取れるときは、明細合計との突合を継続。不一致は勝手に補完せず「要確認」。
- 商品ごとの税額は、税率区分ごとの**印字税額**を原則として明細へ按分。小計・税額・税込合計が一致するように端数調整します。税抜108円の行は、レシート全体の端数調整の結果、税込116円または117円となることがあります。

### 保存写真の左右90度回転

- 回転ボタンを押すと、クラウドから画像を再ダウンロードせず、表示中の写真が**即座に**90度ずつ回ります。
- 「回転をクラウドに保存」を押した場合にのみ、非公開Storageから原画像を取得し、画素自体を回転させたJPEGで置換します。これによって別端末でも同じ向きになります。
- 保存に失敗した場合は、理由を写真欄に表示します。回転プレビュー自体はそのまま利用できます。

### 2026年10月23日のマルエツレシートの救済（1件限定）

ユーザーが写真で提示した「maruetsu」「2026-10-23」「誤登録合計14,422円」の履歴に限り、編集画面に「今回のまるえつレシートを正しい明細に修正（写真照合済み）」というボタンが表示されます。

## 更新手順

1. 旧版の「設定 → JSONバックアップを書き出す」で、データを別ファイルとして保存。
2. このZIPを解凍し、含まれるWebアプリ用ファイルを**すべて** `https://github.com/highllows-stack/receipt-ledger/upload/main` から上書きアップロード。
3. GitHubで「Commit changes」を押す。
4. `https://highllows-stack.github.io/receipt-ledger/?v=1.4` を開き、画面上部に「即時写真回転・税込再照合 v1.4」とあるか確認。必要ならPCは `Ctrl + Shift + R`。
5. 「履歴 → 2026年10月23日 maruetsu → 購入全体を編集・明細を分割」。写真の回転ボタンを試し、該当履歴専用の修正ボタンから候補を読み込み、最後に「変更を保存」。

**SQLとEdge Functionの再デプロイは不要**です。OCR原文からの無料再解析はVision APIを呼び出しません。保存写真の再OCRはVisionを追加で1回呼び出すため、無料枠外の料金が発生する場合があり、事前確認を表示します。

## 検証範囲と注意

- 提供写真から転記したレシート形式による自動テストで、9商品行・数量11点・税抜¥1,600・印字8%税¥128・税込¥1,728の一致を確認。
- 税抜表示、税込表示、合計未読、ポイント番号・レジ番号誤登録防止をテスト。
- 模擬購入履歴とレシート写真を用いたPC／スマホ幅ブラウザテストで、90度回転プレビュー、JPEG回転保存、専用明細候補の読み込み、保存前の履歴不変更、保存後¥1,728への訂正を検証。
- **実際のGoogle Cloud Visionの再OCRと、利用者のSupabaseアカウントへの保存・同期は検証できていません**。写真が撮影時に読めなかった場合、新しい解析でも商品が復元できないことがあります。原写真を見ながら手で修正してください。
- 類似した別レシートまで「同じもの」と自動修正しないため、専用の救済操作は指定の日時・購入先・誤合計に限定しています。
