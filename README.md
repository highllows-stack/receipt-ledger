# くらしのレシート v1.1 — レシート写真確認・OCR解析改善

Android/Windows共通PWA。v1.0の家計簿、計上月配分、学習・分類推測、食費グラフ、Supabase同期を維持します。

## 変更点

1. **レシート写真の非公開保存**：OCRの際に圧縮JPEGをSupabaseの非公開 `receipt-images` バケットに保存。履歴の「購入全体を編集・明細を分割」を押すと写真と明細を並べて表示。拡大・縮小、別タブで拡大、OCR原文表示あり。
2. **以前の購入にも写真添付可能**：v1.0以前は画像自体を保存していなかったため、古いレシート写真は新たに選んで添付してください。過去の画像を自動復元することはできません。
3. **商品名・金額の読み取り精度を改善**：Google Cloud Visionの `DOCUMENT_TEXT_DETECTION` は従来どおり1回。OCR文字列に加え、文字の座標から再構築した行も解析。消費税、対象額、合計、小計、レジ、決済、ポイントなどを商品明細と誤認しにくくしました。
4. **読み取れなかったら「要確認」で保存**：OCRが税額しか認識しない場合、架空の商品金額は計上せず、「未読み取り」0円の仮明細として**写真付きで保存**。履歴で写真を確認しながら、商品の追加・削除・分割・分類・月別配分を修正できます。登録後、要確認の購入があれば編集画面を自動表示します。
5. **OCR原文から無料再解析**：編集画面の「OCRが読み取った原文を表示」から、認識した文字を再解析して明細候補を追加可能。Vision APIを再呼出ししないため追加料金は発生しません。
6. **写真の期限**：写真は登録後約30日でアプリからは表示しません。アプリを開いたとき期限切れ写真の削除を試みます。アプリを開かない間も自動削除したい場合は、下記の「定期削除ジョブ」の設定が必要です。構造化された購入履歴は削除しません。

## 最初の更新手順（順番が大切）

1. 現行のアプリで「設定 → JSONバックアップを書き出す」を実行する。**JSONは画像を含みません。**
2. Supabase SQL Editor `https://supabase.com/dashboard/project/javznmfmrahigswpkgxz/sql/new` で、セットアップZIPの `receipt-storage-migration.sql` を実行する。既存テーブルは削除しません。これにより `purchases` にメタデータ列と本人専用の非公開Storageバケット・RLSを追加します。
3. Supabase Edge Functions → `receipt-ocr` → Codeで、セットアップZIPの `receipt-ocr-edge-function.ts` に置き換えて **Deploy updates**。既存の `GOOGLE_VISION_API_KEY` はそのまま使用し、キーを入力し直す必要はありません。
4. Web更新用ZIPの**中身のみ**を GitHub `highllows-stack/receipt-ledger` リポジトリの **main / ルート** にアップロードして Commit changes。セットアップZIPのSQL/EdgeコードをGitHubにアップロードしないでください。
5. `https://highllows-stack.github.io/receipt-ledger/?v=1.1` を開き、ヘッダーに「写真確認・読み取り改善 v1.1」と表示されるか確認。更新されない場合はChromeで Ctrl+Shift+R またはPWAを閉じて再度開きます。

## レシート写真を見て修正する

- 「登録」→ 撮影または画像を選択 →「選択したレシートを自動登録」。画像は最大5MBに圧縮してクラウドに保存します。
- 「履歴」→ 該当購入を展開 →「購入全体を編集・明細を分割」。PCは左に写真、右に編集欄、スマホは上下表示になります。商品名、分類、金額、数量、計上月などを修正後に「変更を保存」。
- 読み取り失敗の仮明細は、写真を確認して正しい商品の行を追加し、不要な「未読み取り」を削除してください。仮明細の0円は支出に含まれません。
- 以前のレシートに写真を付けるには、その購入履歴を開いて「写真を追加・差し替え」から画像を選択します。この場合、再OCRは行われません。
- OCR文字列から追加候補を見つけたいときは「OCRが読み取った原文を表示 → 原文を明細候補として再解析」を使えます。明細は追記されるため、重複行がないか確認してください。

## 保存・プライバシー・無料枠

- 画像は非公開バケットに置き、RLSでアップロード者のみ読み書き可能です。閲覧には短期間（10分間）の署名付きURLを使用します。公開GitHubやブラウザコードに秘密鍵は置きません。
- **写真の物理削除をログインしなくても毎日実行する場合**：セットアップZIPの `receipt-photo-cleanup-edge-function.ts` を新しい `receipt-photo-cleanup` Edge Functionにデプロイし、関数の **Verify JWTをOFF** にします。代わりに `RECEIPT_PHOTO_CLEANUP_TOKEN`（24文字以上の強いランダム文字列）をEdge Secretsに登録します。`receipt-photo-cleanup-schedule-template.sql` のプレースホルダーを同じトークンに置き換えて SQL Editorから実行すると、Vault＋pg_cronによる日次ジョブを設定できます。**トークンをChatGPTやGitHubに送らないでください。** この設定が終わるまでは、写真の実削除はアプリを開いたときの試行に限られます。
- 30日を過ぎるとアプリは新しい写真表示URLを発行しません。画像が期限切れでも購入商品・金額・分類・計上月はそのままです。
- 今回のOCR強化はVisionへの**追加API呼び出しなし**で実行します。Google Cloud Vision、Supabaseの無料枠は従来どおり適用されます。ストレージ使用量が増えるため、無料枠超過には注意してください。
- 撮影状況やレシート書式によって正確性は変わります。OCR候補を信用して自動で税額を購入商品にはせず、**必ず要確認として編集可能**にしてあります。

## 動作確認状況

- JavaScript構文チェック、Edge Function TypeScript静的チェック、OCR税額除外テスト、PC/Android相当のブラウザ画面で編集フォームの操作・保存テスト、文字認識が税額しかないケースの仮明細・写真メタデータ保存テストを実施しました。
- **実際のSupabaseとGoogle Cloud Visionの通信、非公開写真のアップロード/取得、実機での撮影は未検証**です。初回はテスト用のレシート1枚で検証してください。クラウド保存失敗時には購入記録を作らず、元画像を選択し直せるようにしています。
