# くらしのレシート v1.2 — カード番号除外・税込計算・明細/合計照合

## 今回の修正

- ポイントカード番号、会員番号、ポイント、消費税、対象額、合計、小計、支払、値引きを商品から除外（改行・空白混在にも対応）。新たに保存するOCR原文の会員番号は伏せ字化。
- レシートの印字合計、税額、税抜小計を調べ、**税抜と判断できる時だけ**商品別税込額に換算。税込レシートでは二重加算しない。
- 8%と10%の混在レシートに対応。税率不明などは推測し、無理に確定させず「要確認」にする。国税庁ではレシートごと、税率ごとに1回の端数処理があるため、単品の円単位は必ずしも一意に導けません。
- 読み取った商品合計・加算税額・印字された合計・差額と、その判断理由を購入履歴の**写真付き編集画面**に表示。
- 以前の誤登録を再解析するボタンを「編集欄と入れ替える」に変更。確認ダイアログを出し、**明示的に保存するまで**過去のデータは変更しない。同じ商品と特定できた行は従来の計上月・配分割合を保持し、金額を按分し直します。対応付けできない行は購入月に初期化するため、保存前に確認してください。
- 一致していない場合、架空の調整商品を作らず「要確認」にする。ポイント利用は支払い方法の場合があるので、自動値引きしない。
- 明細が未読み取りなら、写真付きの0円仮明細にして手動入力できるようにする。

## 更新方法

1. 現行アプリ「設定 → JSONバックアップを書き出す」を押して保管する。
2. このZIPを解凍し、中の**15個のWebアプリ用ファイル**をGitHubリポジトリ `highllows-stack/receipt-ledger` の `main` ルートへ上書きアップロードして Commit changes。
3. GitHub Pages反映後、 `https://highllows-stack.github.io/receipt-ledger/?v=1.2` で開く。
4. 「履歴 → 購入全体を編集・明細を分割」で写真・照合結果を確認する。誤登録の場合「OCR原文から明細を再作成」を押して結果を確認、必要な税率・内訳・月別配分を直して保存する。

## 課金・SQL

- **新しいSupabase SQLやEdge Functionの変更は必要ありません。** 既存v1.1のGoogle Cloud Visionによる**1画像1回**の認識結果（文字列とレイアウト）をブラウザ側で再解釈するだけです。
- 追加の生成AI有料APIは使用しません。Google Cloud Visionの既存の枠や料金は変わりません。
- 税率が明示されない混在レシートでは、個々の商品の税込金額が推定になります。照合が一致しても誤読の可能性は残ります。
- お使いのSupabaseの実際の履歴・写真にはこちらからアクセスしていないため、更新後の個別のレシートについては実機で検証してください。
- バックアップのJSONはクラウドの全履歴を必ずしも含まない場合があります。クラウド同期状態を確認し、重要な履歴はCSVでも保管してください。
