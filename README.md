# くらしのレシート v2.1 — OCR金額の矛盾検査・誤った税込合計の防止

v2.0までの機能（写真の回転・写真付き編集、商品別電卓、月別重量・割合・金額配分、学習・予測、Supabase同期）を引き継ぐ累積更新版です。

## なぜ修正したか

2026年10月24日のマルエツのレシートは、税抜小計576円、8%消費税46円、税込合計622円、預り1777円、釣銭1155円です。OCRが「小計46円・税額622円・合計1198円」と誤認識したとき、旧版は576+622=1198円を誤って参考合計としました。

## 変更内容

- **税額の妥当性を必ず検証**: OCRで得た金額が税抜額の8%/10%と矛盾する場合、印字税額として使いません。複数税率は税額合計と税率別内訳を検証します。
- **独立した3つの金額根拠を照合**: 「税抜小計＋税額」「印字された合計」「預り金−釣銭」が矛盾すると、誤った税込合計を確定しません。
- **OCRの2種類の読取り結果を別々に検証**: 行の位置情報と通常のOCRテキストを不用意につなげて、別のラベルと数値が結び付かないようにします。
- **矛盾した数値は保留**: 例「税額622円」を「税額として不採用」と表示します。税込への自動変換で捏造しません。
- **現金差額等からの参考計算を区別**: 印字税額を確認できなくても税抜小計576円と現金差額622円が整合する場合、税額46円を「参考推計」と明記。印字済みの税額とは区別し、「要確認」を残します。
- **明細と参考合計の差額表示**: 印字された合計自体が読めていなくても、預り−釣銭からの参考合計と明細との差を表示します。
- **税込参考合計を編集欄に入力**: 確認ボタンで参考合計を編集欄に反映できます。**商品明細は自動で書き換えず、最後に「変更を保存」を押すまで履歴には反映されません。**
- **10月24日の既存699円などの誤登録修正**: 以前からある「写真照合済み3商品・税込622円に修正」のボタンを引き続き使用できます。

## インストール

1. 旧版の「設定 → JSONバックアップを書き出す」で必ずバックアップを保管します。
2. ZIPの**中身15ファイル**をGitHubリポジトリ `highllows-stack/receipt-ledger` の `main` ルートへ上書きアップロードし、Commit changesを押します（ZIP自体はアップロードしません）。
3. `https://highllows-stack.github.io/receipt-ledger/?v=2.1` を開き、見出し「税額の誤読防止・金額証拠照合 v2.1」を確認します。古い版が表示される場合はCtrl+Shift+Rまたはアプリの再起動を行い、ブラウザデータ削除はしないでください。
4. 「履歴 → 2026年10月24日のmaruetsu → 購入全体を編集」を開き、「写真照合済み3商品・税込622円に修正」を使って商品・税額・計上月を確認し「変更を保存」。

**今回、追加のSupabase SQL・Edge Function設定変更は不要**です。OCR再処理は保存された文字列・位置情報だけを使う限りGoogle Visionの追加呼び出しは不要です。写真を再OCRする場合は従来のGoogle Cloud Vision利用条件が適用されます。

## テスト範囲・注意点

- JavaScript構文チェックと、実際に送られたレシートの金額を転記した回帰テストに加え、誤読（金額入替・異常税額・税額の読み落とし）、税込表示、8/10%混在、商品欠落のケースでチェックしました。
- この環境ではChromiumからlocalhostへのブラウザ接続が管理者により遮断されたため、画面の実動作テストおよび本番Supabase接続は未確認です。表示または保存で問題があればメッセージとスクリーンショットを確認します。
- OCRが商品名や価格そのものを読み落とした場合、数値の一致だけで商品を復元することはできません。写真を見ながら修正してください。
- **既存履歴は更新だけでは修正されません**。修正ボタン等で候補を確認し、保存してください。
# v2.2 更新内容（2026-10-25）

- 商品別の電卓に「％引き」「円引き」の入力を追加。割引後の計算式を確認して商品金額へ反映できます。割引率は0～100％、円引きは商品金額以下に制限します。
- OCRの金額ラベルが誤認識された場合、税率上あり得る「小計＋税額＝税込合計」の数字の組み合わせを**参考候補**として表示します。印字根拠が不確かな数字は自動的に税込合計・税額へ採用しません。
- PWAキャッシュをv2.2へ更新。
